Flat collection of `flutter_test` files under `test/`, one per feature area (auth, payments, notifications, shop, history, legal, etc.), sharing a single helper in `test/helpers/mock_app.dart`. The helper defines fake repository implementations (`FakePaymentsRepository`, `FakeRecipientChoiceRepository`) that implement the production repository interfaces from `features/*/data/*_repository.dart`, and exposes `pumpMockApp`, which wraps `LidapayApp` in a `ProviderScope` with Riverpod overrides for every feature's repository provider plus `sharedPrefsProvider` and `checkoutLauncherProvider`. Tests are split into two styles: integration-style `testWidgets` that drive screens through `WidgetTester` (e.g. `auth_flow_test.dart`, `payment_flow_test.dart`, `orders_screen_test.dart`) and pure unit tests against data models / parsers (e.g. `api_models_test.dart`, `validators_test.dart`, `phone_number_formatter_test.dart`). External dependencies such as `app_links` are replaced by local fakes implementing the same interface (see `_FakeAppLinks`), keeping tests deterministic and network-free.
