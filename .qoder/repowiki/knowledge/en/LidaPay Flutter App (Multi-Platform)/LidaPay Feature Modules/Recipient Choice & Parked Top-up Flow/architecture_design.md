Three-layer leaf feature under `lib/features/recipient_choice/`:
- `data/` defines the domain contract (`RecipientChoiceRepository` abstract class in `recipient_choice_repository.dart`) plus its single live implementation (`RemoteRecipientChoiceRepository`) which calls `ApiClient` against `ApiEndpoints.recipient*` and `topups/{id}/status`. Models (`recipient_models.dart`) — `RecipientChoice`, `RecipientEligibility`, `RecipientDecision`, `TopupOrderStatus` — are `Equatable` DTOs with flexible JSON parsers built on `payloadPool`/`stringField`/`numberField`.
- `providers.dart` is the Riverpod layer: it wires `recipientChoiceRepositoryProvider`, exposes `pendingRecipientDecisionsProvider` (a `StateNotifierProvider` tracking active pending decisions per user key), `recipientEligibilityProvider` (preflight family), `recipientDecisionProvider` (per-decision family), and `topupStatusTrackerProvider` (a `StreamProvider.autoDispose.family` that polls every 3s until terminal). Idempotency keys for `respondToDecision` are generated by `newDecisionIdempotencyKey`.
- `screens/` holds the two entry points: `PendingTopupScreen` (sender-side waiting surface with countdown ring) and `RecipientDecisionScreen` (recipient-side choice UI). `widgets/pending_recipient_decisions_banner.dart` renders the in-app recovery banner for missed push notifications.
Dependency direction is one-way: screens → providers → repository → ApiClient; models have no dependencies on the rest of the app.
