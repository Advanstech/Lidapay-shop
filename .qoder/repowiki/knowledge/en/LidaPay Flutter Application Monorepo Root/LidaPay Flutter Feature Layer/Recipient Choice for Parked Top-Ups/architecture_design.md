Three-layer leaf feature under `lib/features/recipient_choice/` with one-way dependency direction screens → providers → repository → ApiClient:
- `data/recipient_choice_repository.dart` defines the `RecipientChoiceRepository` abstract contract (eligibility preflight, pending-decisions list, single decision fetch/respond, top-up status poll). `data/remote_recipient_choice_repository.dart` is the sole implementation calling `ApiClient` against `ApiEndpoints.recipient*` and `topups/{id}/status`; it also normalises Ghana phone numbers by probing both `0…` and `233…` shapes.
- `data/recipient_models.dart` holds domain DTOs (`RecipientChoice`, `RecipientEligibility`, `RecipientDecision`, `TopupOrderStatus`) as `Equatable` classes with flexible JSON parsers built on `payloadPool` plus `stringField`/`numberField`/`dateField` helper lists so multiple backend field names resolve to one model property.
- `providers.dart` is the Riverpod layer: a single `recipientChoiceRepositoryProvider` wires the repo; `pendingRecipientDecisionsProvider` is a `StateNotifierProvider` tracking active pending decisions per user key (anon/session id / phone / username); `recipientEligibilityProvider` and `recipientDecisionProvider` are `FutureProvider.autoDispose.family` instances keyed by query tuple or decision id; `topupStatusTrackerProvider` is a `StreamProvider.autoDispose.family` polling every 3s until terminal. Idempotency keys for `respondToDecision` come from `newDecisionIdempotencyKey(decisionId, choice)`.
- `screens/pending_topup_screen.dart` is the sender-side waiting surface with a countdown ring and background settlement polling; `screens/recipient_decision_screen.dart` is the recipient-side choice UI. `widgets/pending_recipient_decisions_banner.dart` renders the in-app recovery banner for missed push notifications and navigates via GoRouter to `AppRoutes.recipientDecision`.
