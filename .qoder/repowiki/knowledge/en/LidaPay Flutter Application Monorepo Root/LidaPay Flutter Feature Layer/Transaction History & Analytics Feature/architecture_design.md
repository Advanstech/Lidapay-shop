Layered feature under `lib/features/history/` with one-way dependencies: screens → providers → repository interface → remote/mock implementation → core network layer.
- `data/history_repository.dart` declares the `HistoryRepository` abstract contract (`getTransactions`, `getStats`, `getByDateRange`) so UI never touches HTTP directly.
- `data/remote_history_repository.dart` implements it against `/api/v1/transactions/*` endpoints (paged feed, stats, date-range) and merges ActivityFeed + Lida Value history + shop orders + points; `mock_history_repository.dart` provides test/dev data.
- `providers.dart` is the Riverpod entry point: `historyRepositoryProvider` swaps mock/live in one line, `StateNotifierProvider<HistoryController, AsyncValue<HistoryState>>` owns pagination (page size 10, sentinel row for `hasMore`), client-side filtering via `HistoryFilter.matches`, pending-settle polling (15s timer up to 10 attempts), and two `FutureProvider`s (`transactionStatsProvider`, `historyAnalyticsProvider`) that aggregate chart-ready series from the wider window.
- `screens/history_screen.dart` renders the paged, grouped-by-day ledger with sticky headers, pull-to-refresh, and filter chips; `analytics_screen.dart` consumes `historyAnalyticsProvider`.
- `widgets/` holds reusable chart components built on `fl_chart` (`SpendCurve`, `OutcomeBreakdown`, `WeekdayActivityBars`, `CategoryBars`) plus modal sheets (`HistoryFilterSheet`, `TransactionDetailsSheet`).
- Domain/state classes live in `data/history_models.dart` (`HistoryFilter`, `TransactionStat`, `HistoryAnalytics`, `TransactionInsight`) and are consumed by both layers.
