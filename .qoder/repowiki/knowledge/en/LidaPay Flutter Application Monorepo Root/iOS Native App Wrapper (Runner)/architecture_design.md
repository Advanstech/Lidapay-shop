Standard Flutter iOS Runner layout with three layers:
- Application entry: `AppDelegate.swift` extends `FlutterAppDelegate` + implements `FlutterImplicitEngineDelegate`, initializes Google Maps via `GMSServices.provideAPIKey` using a build-time `GOOGLE_MAPS_API_KEY` from `Info.plist`, and registers plugins through `GeneratedPluginRegistrant.register`. `SceneDelegate.swift` is a thin subclass of `FlutterSceneDelegate`.
- Build configuration: `Podfile` pins iOS 15.0, uses CocoaPods (`use_frameworks!`) to pull in Google Maps, Firebase Core/Installations/Messaging, GoogleUtilities, PromisesObjC, nanopb, and Google-Maps-iOS-Utils; `flutter_install_all_ios_pods` and `flutter_additional_ios_build_settings` integrate Flutter's pod helper. `Flutter/Local.xcconfig.example` documents where to place the gitignored API key.
- App metadata: `Runner/Info.plist` declares bundle id `com.advansistechnologies.lidapay.payment`, URL scheme `lidapay`, Face ID / location usage descriptions, background modes (`fetch`, `remote-notification`), and scene configuration pointing at `Main.storyboard`.
Dependency direction is one-way: this native layer depends on Flutter SDK, Google Maps, and Firebase pods; it does not expose Swift APIs back to Dart beyond what the generated plugin registry provides.
